# 第五阶段：旧数据兼容与回归

本阶段在 `feat/member-ui-polish` 本地工作区完成，延续前四阶段修改。没有提交、创建分支、推送或部署到 Firebase 生产环境。

## 备份与数据保护

修改前同时备份了源码（含未提交和未跟踪文件）、工作区差异、已安装 APK，以及模拟器应用的 `files`、`shared_prefs`。备份位于工作区外层的 `verification/phase5-20261128/backup/`。

自动化测试使用测试数据；交付前恢复原应用数据，再安装并打开最新 Demo APK。恢复过程按文件比较内容，原有账号、报名、签到、草稿、评价、匿名名称和已读状态均需保留。测试数据与用户数据恢复的结果记录在同目录的验证报告中。

## 兼容规则

- 本地快照继续支持 AB v1、共享快照 v2–v7，以及 CE 原始 v1 格式。新写入统一使用 `SnapshotJson.CURRENT_VERSION`，当前为 7。
- 旧数据缺少通知定位、回答历史、综合分或报名轮次等可选字段时使用兼容读取；不凭空补造签到记录，也不把旧评价自动认定为有效参与。
- 无报名轮次的旧签到只有在签到时间不早于当前报名时间时才有效。取消后重新报名不能继承旧签到。此前已保存的评价内容保留，综合分仍依照第四阶段资格规则计算。
- 旧单条回答迁移为固定 ID 的回复；多条历史回答保留各自 ID。重复读取不会重复迁移或补发未读通知。
- 云端旧 `answerQuestion` 接口继续返回最新回答字段，同时事务性保存完整回答历史、新回复和对应通知。Android DTO 和离线快照保留这份历史。
- 缺少评价可选详情的旧记录仍可读取。未指定可见范围的早期评价沿用公开规则；不能识别的显式可见范围按私密处理，在列表、对话、图片权限、草稿和综合评分中一致生效。
- 旧互动存档补齐通知集合的默认值，同时保留私密回复、匿名名称、点赞、删除标记、黑名单和举报结果。
- 未来版本、损坏的主快照不会被新种子数据覆盖；AB 和 CE 两份不同的旧数据不会自动合并。中断写入使用 Android `AtomicFile` 恢复已提交数据。

## 回归修复

1. 修复云端旧问答接口只写新回复、不更新旧回答字段的问题，避免旧客户端和离线缓存等待不到回答。
2. 修复缺少评价详情时的读取错误，以及未知隐私值可能被视为公开的问题。
3. 修复旧版独立签到页仍向未签到者展示评价表单的问题。
4. 恢复活动未结束时，未签到参与者从活动记录进入签到的入口；活动结束后仍要求有效签到才能评价。
5. 恢复问答页原有的全部／未回复筛选、左右滑动、头像预览、最新组织者回答预览与关闭提示。回答预览从新的互动数据读取，遵守删除和屏蔽权限；继续支持多轮回复。回复使问题移出未回复列表时，当前对话保持打开，直到用户主动返回。
6. 恢复个人资料兴趣选项的选中状态语义，便于辅助功能识别和界面测试验证。
7. 更新仍引用定位、单次回答、旧收件箱、旧签到统计和旧快照版本的回归测试。按钮动画完成后再检查操作结果，保留现有动效。
