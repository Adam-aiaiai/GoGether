# Member C / E 集成分支

## 来源与范围

- 日期：2026-11-19。
- E：`origin/feat/member-e-attendance`，`6e1ac916e3b535b7cf2f4a528db3dbedc03f9e11`。
- C：`origin/feature/registration-avatar-group`，`59f5f15afebd1b2a6e0c74c820cd49b94d1594a0`。
- 目标：新分支 `integration/member-c-e-attendance`。不修改来源分支，不合入 main，不引入 A/B/D 的功能分支。
- C 分支在共同骨架上增加参与者头像重叠、展开/收起、姓名、更多人数和名单变化测试；并未包含真实报名服务器。
- 本次保留 C 的组件与动画、E 的二维码/定位/出席/评价/草稿/图片隐私功能，连接双方实际数据链路。

## 统一后的调用链

活动详情 → `ParticipantsCard` → 主 Repository 的正式报名、候补；

活动详情「Check-in & meeting」或管理页「查看签到与出席」→ `RepositoryCheckInScreen` → `PrototypeViewModel` → `RegistrationAttendanceBridge` → 同一个主 Repository + E 私有签到/评价存储。

1. 身份只读取当前 Repository 登录用户。仍为 Demo 登录，非安全认证。
2. C 管理报名、取消、FIFO 补位、正式名单和容量；E 不复制一份固定名单作为资格来源。
3. E 每次提交重新检查当前用户、当前活动、当前报名状态。单机 `LocalDataLock` 防止 C 改资格与 E 写签到/评价在同一进程中交错；不能替代后端事务。
4. 普通编号如 `event-1` 通过 `UUID(nameUUID("gogether-ce-v1:" + eventId + ":" + createdAt))` 适配旧二维码协议。保存 `sourceEventId`，不更改 C 的活动 ID。活动重置后不会继承旧实例的签到或私密评价。
5. B 当前只有文字地址。组织者从具体活动确认实际 GPS 位置为固定集合点，保持原组织者、活动 ID、开始及结束时间；不另造一场十分钟后开始的活动。参与者不能设置或修改。坐标为 WGS84，双方仍需在 200 米内。
6. 一个活动的固定集合点当前不可自行重设。未来 B 提供坐标、编辑活动时间/地点时，需要明确坐标系、版本、已签记录和旧码失效策略；当前资料不匹配时拒绝旧码。
7. 自动签到窗口仍为开始前后各 30 分钟、含端点，且不能超过结束时间。取消或标记完成阻止新签到；无手动开启开关。取消操作仍由原管理页执行，连同 C 报名/候补一起更新。
8. C 正式人数与 E 实际出席分别计算。已签到者随后取消报名时保留真实签到事实；当前正式名单移除该人并按 C 原规则补位。是否禁止签到后取消报名仍由小组确认，本次未添加该限制。
9. E 的记录投影回原管理页，头像名单仍仅表示正式报名。E 出席名单可保留已签到但后来退出者，不能把其计为正式名额。
10. 正常活动详情、个人历史中的已结束活动统一进入 E 完整评价（分项、标签、匿名、仅组织者可见、图片、草稿），不再分流到旧简易表单。没有设置过集合点的活动也可评价：其记录显式没有 GPS 坐标，不能生成或接受签到凭据。原评分/评论会继续展示并阻止重复评价。
11. 页面和提交统一按“状态为 COMPLETED，或已到结束时间”开放评价；取消活动始终拒绝新评价，仍须当前用户为正式报名者。活动完成不会伪造签到记录。非匿名姓名从实时用户资料读取（包括新用户及改昵称），匿名仍显示“匿名参与者”，内部账号关联保持。
12. Profile 的 E 入口由 `CombinedCheckInBackend` 路由：绑定主活动的记录读取实时 C 数据；旧独立扫码演示继续走旧来源。即使主活动消失，绑定记录也不会回落到固定 Alice/Bob 模拟权限。

## 保存与同步边界

- `LocalSnapshotStore` 在一份 JSON 中持久化主活动、用户资料、报名、候补、通知、旧签到和旧反馈；保存成功后才发布状态，失败恢复原状态，避免补位半成功。
- 应用重启保留活动实例及报名数据；不把 Demo 登录恢复当成真实认证，重新选择用户。
- E 继续使用既有私有 SharedPreferences/图片目录，保存签到、评价、草稿和待确认提交。活动记录使用独立的版本化 JSON，兼容读取旧二维码字符串存储；本机活动记录不等于二维码凭据。管理页只投影签到，不将私密评价复制到公共快照。
- E 记录/图片依旧按用户和活动隔离。匿名隐藏展示身份但保留内部账号关联。当前权限属于本机演示，不是后端保护。
- 活跃 E 出席页面沿用 10 秒刷新及手动重试；主 Repository 状态变化会刷新资格/关闭状态；本机签到存储变更会刷新管理页。
- **没有网络共享、服务端签名、服务端时间或真实登录。** 两台设备独立保存 C 数据与固定集合点，不能据此声称正式双机同步已完成。旧独立二维码演示仍可验证物理扫描流程；真实双机报名/签到更新仍待统一后端。
- 默认活动种子只在首次没有本机快照时建立，后续不会重启自动“刷新”为未来活动。开发时需创建新活动或使用测试夹具；不要清除用户数据来伪造通过结果。

## 可交给组员复核的操作顺序

| 操作 | 预期 |
| --- | --- |
| Alice 打开羽毛球，展开头像 | 与正式报名一致，候补 Emma 不显示成正式参与者 |
| Alice 从管理页或详情进入签到 | 显示本活动，首次到约定地点确认集合点；时间和报名不变 |
| Bob 从同一活动进入 | 正确显示 Bob 的报名状态与集合信息，在窗口内使用真实相机和位置签到 |
| Bob 取消报名，Emma 补位 | 头像名单、E 资格同时改变；旧 Bob 码提交被拒，Emma 可签到 |
| Alice 查看出席 | 姓名、人数和签到时间对应同一活动；可搜索和点头像 |
| Alice 在管理页取消活动 | C 名单按原规则取消，E 不再签发/接受新签到 |
| 同一用户重复扫码 | 不新增第二条记录 |
| 另一活动/另一组织者 | 不继承名单、签到、管理权限或私密评价 |
| 活动结束，正式参与者评价 | 一次提交，隐私、草稿、图片规则保持；候补/未报名者不可提交 |
| 重启并重新选择账号 | 主活动/报名实例不变，E 记录保持，旧账号页面不残留 |

## 验证

见 [TESTING](TESTING.md) 的 2026-11-19 C/E 集成记录。相机返回内容和 GPS 位置在自动化测试中使用受控输入；不把它们等同于真机扫码、实际 200 米场地测量或双设备同步。

## 界面语言约定

App 自带界面统一使用英文，包括 E 的签到、出席、搜索、评价、图片预览、权限说明、错误提示与无障碍标签。日期固定使用英文月份；演示活动与演示名单也使用英文。自动化测试和人工演示输入的姓名、评论、草稿、搜索词及模拟错误同样必须使用英文，不使用中文或中英混杂内容。文档可以继续使用中文。已有用户内容不因语言调整而清空。`EnglishUiCopyTest` 检查生产及测试源码 / 资源中的中文文案和中文系统语言下的日期显示。

## 小组仍需确认

- 后端技术、负责人、身份与活动/报名权威数据接口，以及扫码凭据签发/校验、幂等和同步机制。
- B 的地点经纬度/坐标系/编辑版本、正式入口布局；本分支只做 C/E 联调，不引入 B 的分支。
- C 的签到后取消规则、报名截止后补位规则是否调整；本次保留现有实现。
- A 的真实账号、会话恢复和历史记录入口接入；本分支的持久化不等于 A 的账号模块完成。
- 评价资格目前是结束后仍正式报名，不强制已有签到；评分 1–5，评论选填，提交一次，未加入编辑/删除规则。
