## 已采用的接续方式

- 保留 A 的账号接口、资料编辑、会话恢复、用户隔离、保存失败回滚和四类个人活动。My Events 加入 D 的通知入口、未读数和空列表动作。
- 保留 B 的创建、编辑、取消、复用、筛选、封面、新手与器材字段，以及详情和管理页布局。加入独立公告区及 D 的集合编辑器。
- Profile 与独立 Notifications 页面复用同一个收件箱组件，提供 All / Unread、单条 / 全部已读及活动跳转。批量已读只操作当前用户；失效活动有返回 Explore 的入口。
- 公告拥有独立历史记录，新通知关联公告 ID。详情按组织者或正式/候补成员资格显示公告。旧 A/B 的公告通知及已读状态保留，新记录不会按每个收件人重复显示。
- 集合时间、地点、说明使用 D 的独立字段。未配置时沿用 B 的活动时间/地点；签到页面和地图入口读取相同的集合地点。B 编辑其他内容会保留集合字段；缩短结束时间需同时修正冲突的集合时间。复用只复制集合地点和说明，集合时间默认采用新活动的开始时间；原公告、通知、报名不复制。
- 保留 A/B 的存档入口 `demo-snapshot-v1.json` 与 AtomicFile 写入。内部格式升级为版本 2，支持读取版本 1；旧文件没有新增字段时使用空公告、默认集合信息和无关联的旧通知。保留损坏文件及保存失败回滚行为。
- 保留 A/B 的 AGP 9.4.0。仅补充 D 数据源编译所需依赖，不引入 D 的本机版本降级。
