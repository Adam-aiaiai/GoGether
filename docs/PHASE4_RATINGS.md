# 第四阶段：综合评分与 History

基于本地 `feat/member-ui-polish` 的前三阶段版本继续实施。修改前保存完整源码、差异、已安装 APK 和模拟器应用数据。此阶段不推送 GitHub，也不部署 Firebase。

## 统一规则

- 活动已结束且未取消后，取有效公开参与者评价的总体评分做等权平均，每位参与者每场活动最多一份当前评价。显示一位小数，评价数使用同一组有效记录。
- 排除组织者的评价（包括历史匿名组织者评价）、私密评价、已删除或维护者移除的评价、草稿、回复、无效评分，以及不能核实当前报名与签到资格的旧评价。
- 参与者须有当前正式报名和有效签到。评价时间不能早于签到；普通结束活动的评价不能早于活动结束。保存了报名标识的记录还需匹配当前报名周期。旧记录不补造签到，以已有报名和签到时间核验。
- 匿名公开评价正常计分。个人拉黑不改变全体用户看到的总分；它继续隐藏相关内容并限制互动。点赞、分项评分不改变总体评分。
- 删除后立即重算；重新评价使用新记录，旧归档不再参与。不会因删除或改成私密而重新启用旧评分。
- 没有有效评价：星标旁显示 `—` 和 `No reviews`，不显示 `0.0`。尚未取得评分数据（例如旧云端缓存）：显示 `Unavailable`，不冒充“无评价”。

## 展示位置

My Events → History 的活动卡片，以及 Profile 的 Activity history 预览和 More 历史列表，都在活动标题右侧显示星标、综合分和评价数。个人评分继续单独标注为 `Your rating`。

签到/评价记录列表的已关联活动也显示同一数据；活动评价页使用 `Public participant reviews` 标注同一综合分。不会从当前可见评论列表推算，以免私密权限或拉黑导致不同用户看到不同分数。

## 数据与兼容

`EventRatingSummary` 只包含评分总和及评价数量，不包含作者身份、私密分数或评论。Demo 模式使用原报名/签到记录与当前评价做只读投影，监听评价与社交状态变化实时刷新。正文、匿名别名、举报记录、旧评价归档和个人评分保持原有存储。

Firebase 在服务器读取快照及 reviews 接口时，以同一个聚合函数从事务一致的当前记录计算。删除、维护者处理、重评和幂等重试均不会造成累加漂移。公共汇总不依赖浏览者权限；评论内容仍按权限过滤。`snapshot.eventRatings` 和 `reviews.ratingSummary` 返回相同规则下的结果。

快照升级到版本 7，兼容版本 1–6。旧云端缓存没有总分时保留未知状态；新快照会缓存公共汇总供离线查看。现有课程项目的数据量上限保持不变。

## 测试与手动检查

本机文件位于工作区父目录 `verification/phase4-20261128`。自动化验证包括评分边界、跨账号一致性、匿名/私密/组织者排除、旧签到和报名周期、删除及重新评价、维护者移除、快照兼容、History 布局和前三阶段回归。最终结果记录在 `verification.json`。

测试后恢复原有模拟器数据，并追加两个独立活动：

1. **Phase 4 - Public ratings**：Bob 5 星、Carol 3 星，显示 **4.0 / 2 reviews**。组织者 1 星、私密 1 星及已删除 2 星不计入。
2. **Phase 4 - No public ratings**：只有组织者和私密评价，显示 **No reviews**。

模拟器以 Alice 打开 History。切换 Bob 后，可删除第一项活动的本人评价，检查变为 **3.0 / 1 review**；再提交 2 星评价后应为 **2.5 / 2 reviews**。My Events 和 Profile 的 History 显示应一致。

最终本机结果（2026-11-28）：252 项 Kotlin 单元测试、44 项 Node 单元测试、36 项 Firebase 模拟服务集成测试及 45 项独立 Android 模拟器测试通过；构建和 lint 通过（0 错误，60 项非阻断警告）。最终受影响流程复测为 `OK (12 tests)`。首次运行中的 3 项新 UI 断言改为读取卡片内部未合并的评分语义节点后复验通过。原有记录及偏好逐项保留；手动测试数据的 4.0/2 与空状态已验证。
