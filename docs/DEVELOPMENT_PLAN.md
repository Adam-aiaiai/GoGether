## 后端替换顺序

1. 新增 `FirebaseGogetherRepository`，保留 Fake 供离线开发与测试；先接通会话和公开活动读取。
2. 用用户 UID 绑定资料和报名，设置 Firestore 读取 / 写入安全规则。
3. 将报名、取消、FIFO 补位、通知写入放到可信后端的原子事务中。服务器验证截止时间、活动状态及组织者身份。
4. 使用快照监听同步 UI，定义 loading / error / reconnect 状态。服务器确认前不得显示最终报名成功。
5. 通过幂等请求、重试、两设备压力测试与规则测试后接入正式签到。
6. 二维码内容只作为输入凭据；后端仍验证用户、活动、有效时间、报名资格和重复使用。

## 本阶段暂定规则，团队需再确认

- 最低 Android API 26；设备范围扩大前再评估 desugaring 和兼容性成本。
- 活动容量 2–50（包含组织者）；组织者只能整体取消活动，暂不支持转让组织权。
- 活动默认持续两小时；正式版应增加结束时间字段及完成动作。
- 截止后停止补位；开始前可取消，开始后锁定报名变更。
- Demo 签到允许提前开启；正式版应定义时间窗口、凭据生命周期和迟到处理。
- 已结束活动的正式参与者可反馈，不要求已有签到记录。
- 活动编辑、推送通知、定位排序、二维码、举报 / 封禁属于后续开发范围。

这些选择已在 Demo 文案与测试中保持一致。修改规则时先补充相应测试，再修改 Repository / 引擎，最后调整界面。
