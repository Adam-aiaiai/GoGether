## 应用内的接续

| 流程 | 接续方式 |
| --- | --- |
| A 的登录 / 注册 → B 的发布与发现 | `GogetherApp` 使用统一身份；所有页面通过同一个 `GogetherRepository` 操作 |
| B 的发布 → A 的个人活动 | 创建活动保存组织者 ID 和正式报名记录；Created / Joined 直接从共享快照派生 |
| A 的资料编辑 → B 的详情与筛选 | 修改昵称保留用户 ID；组织者显示和搜索从共享用户表读取 |
| A 的 Created → B 的详情、管理、编辑与复用 | 导航传递原活动 ID；管理与编辑继续核验组织者身份 |
| B 的取消 → A 的 History | 活动与报名同时更新；个人列表使用 B 的状态和结束时间 |
| A 的本地保存 → B 的活动字段 | 统一保存起止时间、截止、经验要求、入门指导、器材和图片引用等字段 |
| A 的身份切换 → B 的草稿与权限 | 页面状态按用户区分；其他账号不能使用当前账号的发布草稿或管理其活动 |

本次整合保留 A 的完整运行代码。对照 B 的 `740de15`，`feature/event`、`feature/explore`、`ManagementScreen.kt` 与 `ui/theme` 没有代码差异。新增联调测试用于验证这些已有模块在一个应用中的完整操作。
