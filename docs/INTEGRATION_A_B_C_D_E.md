自动签到沿用 E 已确认迭代：开始前 30 分钟至开始后 30 分钟（含端点）自动开放，双方距固定集合点不超过 200 m；取消、完成或到达结束时间后关闭。未恢复旧手动开关；`demoCheckInOpen` 仅保留旧数据格式兼容。

评价沿用 CE：总评分 1–5；评论选填，最多 500 字符；最多 3 张图片；匿名隐藏对外身份但内部保留账号；公开/仅组织者可见，默认公开；已提交只读。图片预览、账号/活动隔离、退出恢复草稿继续使用 E 原实现。

## 存档与一致性

- 两个来源格式不同：ABD 为 `files/demo-snapshot-v1.json`，CE 为 `ce_repository_v1` SharedPreferences。不能用相同 JSON 解码器直接替换。
- CE 的 `LocalSnapshotStore` 保留 version 1 读取，后续写入共用 `SnapshotJson` version 2，避免旧写入路径漏掉 B 的新手字段或 D 的集合/公告信息；仍保持其旧契约不恢复 Demo 登录。当前 Application 使用下述整合文件。
- `IntegratedSnapshotStore` 首次加载任意一个已有来源，写入新的 `integrated-snapshot-v1.json`；此后优先读取新文件。保留全部活动实例和用户 ID，不重新播种覆盖旧记录。
- 原 ABD/CE 存档保持原样；E 的 `checkin_prototype_v1`、草稿和私有图片继续使用原位置，不迁移或清空。
- 若同时存在两份不同旧数据且没有新存档，明确失败，不擅自覆盖任意一份；Application 保留原文件并显示临时会话提示。届时需选择来源或进行人工数据迁移，不能视为自动完成双数据集合并。
- Repository 继续先保存再发布、失败回滚；与 E 共用本地发布锁，避免向 E 暴露保存失败的报名状态。这是单进程本地一致性，不是服务端事务。

2. 活动问答在传入 ABD 分支明确属于后续阶段，当前没有问答页面/完整实现；公告不能代替问答。
3. B 的正式地理坐标字段/选点服务、服务器签发二维码、统一服务端时间、C 跨设备抢位和 E 双设备出席同步仍需团队后端。扫码及位置模拟测试不能证明这些能力。
4. 自动开放是本次沿用的 E 迭代，与较早分工中的“签到开关”存在措辞差异，联合验收时按当前决策确认，不偷偷增加第二套冲突规则。
