# 双手机扫码签到原型

> 本文记录此前集成／原型版本。当前签到、定位移除和评价资格以 [第一阶段规则](PHASE1_ATTENDANCE.md) 为准。

> 2026-11-19：E 分支已更名为 `feat/member-e-attendance`。C/E 集成分支另见 [MEMBER_C_E_INTEGRATION](MEMBER_C_E_INTEGRATION.md)：普通活动入口读取 C 实时报名并绑定本场活动；本文以下保留旧独立双手机演示步骤，不代表普通活动已经跨设备同步。

本原型在 `dev/hcc-mvp` 开发，入口为登录后的 **Profile → 扫码签到原型 · 两台手机试用**。它使用真实相机、Android 系统定位和动态二维码；A 的身份、B 的活动、C 的报名与后端签发均为模拟。不会修改现有活动数据或报名逻辑。

## 两台 Android 手机怎么试

1. 两台手机安装同一份 `app/build/outputs/apk/debug/app-debug.apk`，最低 Android 8 / API 26。打开系统自动日期和时间、定位服务；两台手机各自能取得位置即可，不要求连接同一个 Wi-Fi。
2. 组织者手机登录 **Alice**，进入 Profile 中的原型入口。
3. 到达测试集合点，点“定位并设置集合点”，允许精确位置。确认后将这次位置固定下来，测试活动将在 10 分钟后开始、持续两小时；当前已经处于签到窗口。不是每次出码都重新设置中心点。
4. 点“定位并出码”。组织者必须在固定集合点 200 米内；验证后显示动态二维码，按钮变为“刷新二维码”。
5. 参与者手机登录 **Bob**（Carol、David 也可），进入同一个原型入口，点“扫码并定位签到”，允许相机和精确位置，扫描组织者手机上的码。
6. 扫码后读取同一测试活动和集合点，再获取参与者的当前位置；验证成功显示本机签到结果。无需输入经纬度，也不必在两台手机手动设置相同坐标。
7. 用 Bob 再扫一次，应该提示已签到；退出并重新打开 App、重新登录 Bob 后仍保留原型记录。Emma 是模拟候补，Finn 和其他账号为未报名，用于验证拦截。

手机只授予“大致位置”时提示到设置开启精确位置；拒绝权限可返回，不会不断强制弹窗。只打开二维码不需要相机权限。定位失败、权限拒绝和超范围均不产生缺席。

如需换测试场地，Alice 使用“更多 → 另建一场活动”，会生成新的活动编号和固定集合点，之前的签到记录保留。尚未开始的测试活动可以在“更多”中取消；开始后取消权限没有扩大。重新回到组织者页面时需要点击出码以重新定位；页面进入后台会停止位置请求并隐藏二维码。

## 组织者现场签到页

- 组织者主屏限制在手机可用高度内，竖屏上方显示动态二维码，下方通过“已签到 / 未签到”标签切换头像名单与人数。名单自动换行，仅名单区域滚动，二维码与操作按钮保持可见。横屏改为左侧二维码、右侧名单。
- 二维码刷新或暂不可用时保留同样大小的占位，避免下方名单跳动。只有有效码可以扫描。
- 沿用当前模拟报名名单 Alice、Bob、Carol、David（包括组织者）；Emma 候补、Finn 未报名，不进入正式名单。头像尚未接入 A 的资料图片。
- 名单从本场活动的本机记录读取，重新进入或成功刷新出码时重新读取。没有跨设备同步，另一台手机的签到不会自动显示在这里；“未签到”只表示本机未取得签到记录，不能当作缺席。
- 集合信息、完整状态、权限设置、取消活动和另建活动收进右上角“更多”的面板，主屏不堆叠这些内容。
- 在“更多”点击“预览多人名单”可查看 10 个虚构人物的多排效果；点击“返回当前名单”恢复。示例不保存、不产生签到或缺席、不改变报名资格；更换活动时退出预览。按界面要求不显示“示例”“虚构”等说明小字，数据来源和原型限制在本文保留。
- 两组都显示头像和姓名；页面不使用圆点分隔符，返回按钮显示“< 返回”。
- 后续 `PrototypeCheckInBackend.attendance` 将接入 C 的正式名单与后端签到记录，再由 A 提供真实头像和昵称。

## 当前试验参数

集中定义于 `feature/checkin/prototype/PrototypeProtocol.kt` 的 `PrototypePolicy`：

| 项目 | 当前值 | 说明 |
| --- | --- | --- |
| 双方允许距离 | ≤200 米 | 到同一个固定集合点的直线水平距离，边界包含；不是双方相互距离 |
| 签到窗口 | 开始前 30 分钟至开始后 30 分钟 | 两个端点包含；到结束时间后立即关闭 |
| 定位精度估计 | ≤50 米 | 试验值，精度差时等待改善或超时提示，不扩大 200 米范围 |
| 位置年龄 | ≤15 秒 | 使用设备单调时钟衡量，拒绝旧位置、未来位置和已标记模拟位置 |
| 定位请求超时 | 20 秒 | GPS / network 提供者；完成、退出和超时均注销监听 |
| 二维码寿命 | 最长 30 秒 | 不超过签到窗口和活动结束时间；过期边界不再接受 |
| 续码 | 展示约 10 秒后重新定位并签发 | 重新验证时先隐藏旧码，失败停止续码，需点击重试 |

只有 200 米及已有签到窗口是已确认规则，其余参数为原型试验值。室内可能定位慢或漂移，需要两台实体手机实测。不能仅凭结果在 200 米内就证明本人进入场馆，也不能通过精度数字绝对保证真实位置。

集合点和实时定位都使用 Android `LocationManager` 的 WGS84，不混用第三方地图坐标。以后接入 B 的地图选点时必须统一坐标系后再算距离。

## 个人历史与活动评价

- 参与者页面右上角“我的记录”；组织者通过“更多 → 我的记录”进入。列表与详情是独立页面，不增加二维码主屏长度。
- 新读取的有效活动信息会关联当前模拟正式参与者，签到成功后保存签到时间。重开 App、重新登录同一用户后，可以从历史直接进入；无需重新扫描已过期的码。
- 列表支持“全部 / 待评价”，按开始时间从新到旧排列。详情显示活动时间、签到时间及已有评价。
- 到达活动结束时间才允许提交 1–5 分和最多 500 字的可选评论。没有默认评分；提交失败保留当前页面输入；成功后显示已提交内容，不能重复提交。
- 沿用原 Demo 规则：正式参与者可以评价，不强制要求先签到。有效码已关联的活动即使定位失败，也可在结束后评价；不自动记缺席。
- 本机活动、参与关联、签到和评价保存于私有存储；以活动 ID 和用户 ID 隔离，存储层阻止多个服务实例并发重复写入。同一活动 ID 的时间 / 集合点与已保存数据冲突时拒绝覆盖。
- 早期版本只有签到时间、没有活动元信息的旧记录仍保留用于防重与最近签到展示；无法从旧时间记录推断结束时间，需重新读取该活动信息后才能加入历史评价。
- 当前活动仍为 10 分钟后开始、持续两小时。自动化测试使用注入时钟覆盖“扫码成功 → 活动结束 → 评价 → 重启后防重”；没有新增提前结束活动或调整系统时间的产品入口。
- 本地检查不证明活动快照可信，也不能实时知道另一台手机取消了活动。真实身份、实时资格、服务端时间和唯一约束仍必须由后端校验。E1–E6 及选做项见 `MEMBER_E_CHECKLIST.md`。

## 什么是真实的，什么是模拟的

- 真实：相机识别（ZXing Android Embedded）、位置权限、GPS / network 定位、球面距离计算、二维码图像及刷新、页面倒计时、位置失败处理。
- 模拟：Alice 是组织者，Alice / Bob / Carol / David 正式报名，Emma 候补，其余未报名；测试活动不来自 B 的活动列表。手机号或真实账号没有接入。
- 本地保存：测试集合点、取消标记和签到结果存入 App 私有 SharedPreferences。签到键为“活动 ID + 用户 ID”，不保存参与者的原始定位轨迹。原有 Demo 的内存仓库没有改成持久化。
- **二维码携带便于两台离线设备共享的模拟活动快照，不是可信签名。** 不能用它证明身份、凭据防伪或服务器时间；不能直接将此协议用于正式处罚。
- **没有跨设备同步。** 组织者手机不会自动收到参与者签到；取消标记只在本机，另一台设备不能立即得知取消，已发出的码最长仍可存活 30 秒。停止展示不能撤回已拍到的码。正式版必须后端实时检查活动状态。
- 二维码页展示时设置 `FLAG_SECURE`，减少系统截图和录屏；不能阻止另一台相机拍摄。离开页面时取消标志。
- 开发者设备上明确标记的模拟位置被拦截。自动化测试注入测试位置源，只验证规则和状态；不代表通过了实体手机的 GPS 和相机现场验收。

## 后续替换接口

`PrototypeCheckInBackend` 是接入边界：

- `createMeeting` / `hostedSession`：当前 E 现场建立模拟活动，后续换为 B 的活动 ID、集合点、开始 / 结束时间、状态和组织者 ID。
- `issue`：换为后端验证组织者身份、当前位置及活动状态后签发短效凭据；不把签名密钥放进 App。
- `submit`：换为后端根据 A 的登录身份、C 的最新报名状态、统一时间、有效凭据、位置及唯一约束执行签到。当前固定测试名单由 C 的接口替换。
- `cancel` / `isCancelled`：换为 B 的权限与服务端活动状态；正式签到请求必须读取最新状态，不能依赖码内快照。
- `rememberCode` / `history` / `submitFeedback`：当前为本机活动关联、个人记录和评价，后续由 B / C 确认活动与资格、服务端执行保存及唯一约束，A 读取记录展示个人历史。
- `PositionSource`：可替换为小组统一定位服务；保持输出精度、采集时间及统一坐标系。
- 出席查询 / 同步：后端接入时新增，由组织者订阅，当前原型只显示扫码手机自身保存的结果。

新实现放在 `feature/checkin/prototype`；共享接触点仅包括 Profile 入口、Manifest 权限和扫码依赖。原有 `GogetherRepository.checkIn` 接口及 B/C 的业务没有因本轮原型而改动。

## 验收场景

### 名单查找与签到提示

- Bob 的主页面围绕一场活动展示名称、组织者、时间、集合位置、同行人员和一处签到状态。底部操作固定，详细介绍与须知按需打开；小屏、大字体和长错误信息只滚动中间内容。圆角仍统一为 12dp。
- 时间与集合点来自实际扫码获取的本机场次；首次没有场次时明确提示扫码获取，不伪造地址或时间。活动名称“羽毛球交流”和简介来自 E 模块内的展示资料，组织者与同行名单沿用固定 A/C 模拟用户，待 B 提供正式活动资料接口后替换。所有本机场次暂时共用该介绍，按日期区分记录。
- 签到成功后活动背景不变，状态展示签到时间，底部进入对应场次记录；结束后进入该场评价表。跨场次旧回执不会显示为新场次结果，失败显示本次原因。首次扫码读取的信息在定位失败时仍保留，离开页面不会丢失已识别的活动背景。
- “位置”打开集合说明与外部地图入口，使用组织者固定的 WGS84 点；地图应用缺失时给出提示。不同地图提供方坐标处理仍须真机验证，不作为正式地图接入完成。签到说明内保留“扫描其他活动”，避免旧活动结束后阻断下一场扫码。

- Alice 在出码页面点顶部放大镜，按名字查找全部正式参与者；支持中文部分名字、英文大小写及忽略首尾空格。结果同时包含已签到和未签到者，同名用户分开显示。
- 点名单头像，在原有名单区域查看签到信息；上方二维码保持原位，不弹居中确认框。点击收起图标或系统返回可恢复名单，切换分组也会收起详情。搜索结果点击后原位展开，重复点击收起。
- 已签到显示本地时区的日期与时分秒；未签到显示“尚未签到”。查找结果通过分隔线区分，主页面不增加高度。
- Bob 的“签到成功”浮层只在签到结果成功保存后显示，约 2.5 秒后消失（遵循系统辅助功能提示时长）；原有签到记录继续保留。恢复旧记录、无效码及重复扫码不会触发成功浮层。
- Alice 的提示来自新读取到的签到记录，重新读取同一条不会重复提示，多人一次到达合并提示。当前随出码刷新读取本机名单；初次进入已有记录不提示，后台离开清除提示。预览名单不会制造签到通知。
- 两台手机仍各自使用本地存储，因此没有实时双端通知。未来后端提交成功后向组织者同步记录，才可实现 Bob 成功、Alice 随后收到到场提示；不承诺网络传输下严格同一瞬间显示。
- 两种提示背景使用 80% 不透明度（比原先约 93% 更淡、更透明），文字保持不透明，并使用紧凑内边距。
- 根据用户提供的乐刻截图，签到流程内的矩形卡片、按钮、输入框、筛选项、确认框与成功提示统一采用 12dp 圆角半径；查找和更多面板顶部两个角同为 12dp。该值是视觉近似，不宣称为乐刻的源码参数。头像保持圆形，二维码图案及其留白保持方形，不裁切码点。
- 样式集中在 `CheckInStyle.kt`，仅用于 E 的扫码签到、记录与评价流程；不修改全局主题或其他模块共用卡片。查看签到时间继续在名单区域内展示，没有恢复信息弹窗。

- 正常双手机扫码；两个不同的正式参与者扫描同一有效活动码均可签到。
- 组织者或参与者远离固定集合点超过 200 米；组织者移动不能带动中心点移动。
- 精确位置被拒绝、只授予大致位置、系统定位关闭、室内定位精度不足及请求超时。
- 二维码刷新、旧码过期、扫描无关二维码、两台手机时间明显不一致。
- 扫到有效码但定位期间码过期：要求重扫，不能继续使用旧码签到。
- 重复扫码、重启 App、账号切换；候补和未报名拦截。
- 组织者退到后台后停止定位和续码；重新进入后重新验证。
- 原型活动取消 / 结束后本机关闭出码；跨设备取消及时性留作真实后端验收。

## E 的统一入口与活动绑定（2026-11-16）

本轮只修改 `feature/checkin`、E 的测试和文档。A/B/C/D、公共导航、共享模型和仓库保持本轮开始时的内容；历史未提交改动不代表本轮修改。旧 Demo 的活动 ID / 内存仓库不能直接充当可信二维码活动，未擅自将两套存储合并。

### 交给其他模块调用的入口

- `CheckInEntryIntent.activity(context, session)`：指定活动。B 提供活动快照 `PrototypeSession`（活动 ID、WGS84 集合点、开始 / 结束时间），E 严格核对二维码是否属于这场活动。缺失或无效入口数据拒绝进入，不降级为任意活动扫码。
- `CheckInEntryIntent.general(context)`：通用入口。未指定目标时可读取有效活动码；页面已有活动时，主要扫码按钮按该场活动捕获目标。要换另一场，明确点“签到说明与权限 → 扫描其他活动”。现有 Profile 启动方式仍兼容，未修改其源码。
- E 的“记录 → 活动记录 → 进入本场签到”会选择该条记录的活动，并使用相同的指定活动校验。A/B 可后续接入上述入口；现在不修改他们的页面。
- 当前是本地原型的数据契约，活动 ID 沿用原型 UUID。B 的正式模型、现有 Demo 的短 ID 与后端凭据需要约定适配，不能临时生成另一个 ID 冒充同一活动。

### 模拟接口与职责

- `CheckInIdentitySource`：只读当前账号，Android 适配器沿用已有登录状态读取；不从 Intent 或二维码接受用户 ID。不实现 A 的登录功能。
- `CheckInEntry.Activity`：B 提供的活动快照入口，不实现活动创建 / 编辑业务。现有 Alice 现场建场仍仅作为模拟数据工具；指定活动入口不得另建一场替代目标活动。
- `CheckInRegistrationSource`：按活动 ID / 用户 ID 查询报名状态与正式名单；默认 `MockCheckInRegistrations` 沿用固定人员。页面与本地后端注入同一个来源，不实现 C 的报名 / 候补业务。
- 服务端鉴权、凭据签发、取消同步和跨设备写入仍未实现；本轮的客户端绑定不能替代后端核验。

### 需要保留的行为

- 先捕获当前用户与目标活动，再请求权限或打开相机。错误活动在定位、关联历史和保存签到前被拒绝，保留原活动供重试；同 ID 但时间 / 集合点冲突也拒绝。
- 相机返回使用本次请求标识。更换活动后旧相机结果失效；重复回调不重复提交；打开相机造成的页面进入后台不会丢掉本次目标。
- 退出登录或切换账号使旧 E 页面实例失效，清除展示中的活动、名单、记录和提示，停止等待中的定位 / 出码。位置返回后、保存签到前再次核对身份；重新登录原账号也不能复活旧请求。
- 当前活动回执必须匹配用户与活动。不会把 Alice 在本机托管的活动自动交给另一个用户；历史记录仍按用户保留，切换活动不删除原签到。
- 新旧 E 评价表都要求主动选分，评分和评论草稿以用户与活动区分；规则仍是正式参与者结束后可评价，不新增必须签到的限制。

## 出席名单独立刷新与结束后查看（2026-11-16）

## E 的签到提交与结果核对接口

`CheckInSubmissionSource` 是 E 内独立的异步边界；原 `PrototypeCheckInBackend` 继续提供本地活动、报名、记录等模拟数据，不修改 A/B/C 模块。

- `submit(attempt, raw, fix)`：attempt 包含唯一请求 ID、当前用户和完整活动绑定。正式后端应从认证会话确定用户，按请求 ID 幂等处理，并保留活动 + 用户的唯一签到约束。返回确定保存的签到记录；仅明确拒绝且没有落库时抛出 `CheckInRejected`，网络异常不能包装成明确拒绝。
- `resolve(attempt)`：返回 `Saved(receipt)`、`NotSubmitted` 或 `Unknown`。`NotSubmitted` 必须保证原请求已终结且之后不会落库；404、缓存未命中、暂未查到、仍在处理及断网均不能当作此结果。正式后端需原子化记录请求终态，或提供等价保证。
- 核对可在二维码失效、签到窗口关闭后进行，无需重新定位。客户端核对返回记录中的账号和活动，拒绝串场响应。远端适配器还应更新 E 的本地记录缓存，保持历史页与确认结果一致。
- `LocalCheckInSubmissionSource` 只适用于当前同步本机后端：本地写入在调用返回前结束，所以可在查无记录时确认未提交；不能将这个判断直接复制到异步服务器。
- `PreferencesPendingCheckInStore` 在发送前保存请求进度，核对完成后按精确请求 ID 清除，旧响应不能清掉新请求。应用进入前台时核对当前活动的待确认请求；手动入口是原底部按钮“核对签到结果”。清除应用数据会清除这些本地进度，正式后端仍须按账号查询与防重。
- 提交和查询各使用 10 秒等待上限。测试通过可挂起的模拟来源注入提交超时、保存后丢失回复及查询失败；普通用户入口仍使用本机来源，不制造真实断网状态。
